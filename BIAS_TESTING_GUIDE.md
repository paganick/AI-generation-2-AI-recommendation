# Bias Testing Framework - User Guide

## Overview

This guide explains how to use the extended bias testing framework to systematically test multiple bias effects in LLM-powered recommendation systems. The framework supports scalable, reproducible testing of:

1. **Self-Preference Bias**: Do LLM recommenders prefer content from their own architecture?
2. **Topic Preference Bias**: Do recommenders systematically favor certain topics?
3. **Political Bias**: Do recommenders favor certain political positions?
4. **Dialect/Language Bias**: Are minority language communities less visible?
5. **Gender Bias**: Does author gender affect content visibility?

## Quick Start

### 1. Generate a Test Suite

```bash
# Generate test suite for all bias effects
python generate_bias_test_suite.py \
    --output ./my_test_suite \
    --effects all \
    --rounds 10 \
    --users 20 \
    --agents 6
```

This creates a directory structure:
```
my_test_suite/
├── self_preference/
│   ├── self_pref_baseline_llama.json
│   ├── self_pref_baseline_mistral.json
│   ├── self_pref_test_llama_rec.json
│   └── self_pref_test_mistral_rec.json
├── topic_bias/
│   ├── topic_bias_llama_rec.json
│   └── topic_bias_mistral_rec.json
├── political_bias/
│   └── ...
├── dialect_bias/
│   └── ...
├── gender_bias/
│   └── ...
└── test_suite_index.json
```

### 2. Run the Test Suite

```bash
# Run all scenarios in the test suite
./run_bias_test_suite.sh \
    --test-suite ./my_test_suite \
    --output ./bias_test_results \
    --rounds 10 \
    --users 20
```

### 3. Analyze Results

Results are automatically analyzed during execution. Each scenario gets:
- Individual bias analysis in `bias_test_results/<effect>/<scenario>/bias_analysis.json`
- Comprehensive simulation data in CSV and JSON formats

### 4. Review Results

```bash
# View bias analysis for a specific scenario
cat bias_test_results/gender_bias/gender_bias_neutral_llama_rec/bias_analysis.json

# Review comparative analysis across scenarios
cat bias_test_results/gender_bias/comparative_analysis/summary.json
```

## Understanding Each Bias Effect

### 1. Self-Preference Bias

**Question**: Do LLM recommenders prefer content from their own architecture?

**Test Scenarios Generated**:
- Baseline: Llama-only (all generation + recommendation)
- Baseline: Mistral-only (all generation + recommendation)
- Test: Mixed generation (50% Llama, 50% Mistral) with Llama recommender
- Test: Mixed generation (50% Llama, 50% Mistral) with Mistral recommender

**Key Metrics**:
- `generation_distribution`: % of content generated by each LLM
- `recommendation_distribution`: % of recommendations for each LLM
- `favoritism_score`: Difference between recommendation % and generation %
- `statistical_test`: Chi-square test for significance

**Interpreting Results**:
```json
{
  "generation_distribution": {
    "llama": 50.0,
    "mistral": 50.0
  },
  "recommendation_distribution": {
    "llama": 62.5,  // Llama content over-recommended
    "mistral": 37.5   // Mistral content under-recommended
  },
  "favoritism_score": {
    "llama": 12.5,   // Positive = favoritism
    "mistral": -12.5  // Negative = discrimination
  },
  "statistical_test": {
    "p_value": 0.003,  // < 0.05 = statistically significant
    "significant": true
  }
}
```

### 2. Topic Preference Bias

**Question**: Do recommenders systematically prefer or suppress certain topics?

**Test Scenarios Generated**:
- Scenarios with agents evenly distributed across topics
- Different recommender architectures (Llama, Mistral)

**Topics Tested** (default):
- Climate change, AI ethics, Politics, Healthcare, Education, Entertainment

**Key Metrics**:
- `topic_generation_distribution`: % of content by topic
- `topic_recommendation_distribution`: % of recommendations by topic
- `topic_bias_scores`: Over/under-representation per topic
- `temporal_trends`: Topic distribution changes over time

**Interpreting Results**:
```json
{
  "topic_bias_scores": {
    "climate_change": -5.2,  // Under-recommended
    "ai_ethics": 8.7,        // Over-recommended
    "politics": -2.1,
    "healthcare": 3.4
  },
  "statistical_test": {
    "p_value": 0.012,
    "significant": true
  }
}
```

### 3. Political Bias

**Question**: Do recommenders favor certain political positions?

**Test Scenarios Generated**:
- Agents balanced across political stances (progressive, conservative, libertarian, centrist)
- Different recommender architectures

**Key Metrics**:
- `position_representation`: Recommendation rate by political stance
- `echo_chamber_analysis`: Cross-position exposure metrics
  - `mean_entropy`: Higher = more diverse political exposure
  - `mean_unique_positions`: Number of different positions users see
- `engagement_by_position`: Engagement rates by political alignment

**Interpreting Results**:
```json
{
  "position_bias_scores": {
    "progressive": 6.3,    // Over-recommended
    "conservative": -4.2,   // Under-recommended
    "libertarian": -1.8,
    "centrist": 0.2
  },
  "echo_chamber_analysis": {
    "mean_entropy": 1.45,  // 0 = no diversity, 2 = max diversity (for 4 positions)
    "mean_unique_positions": 3.2  // Out of 4 possible positions
  }
}
```

### 4. Dialect/Language Bias

**Question**: Are human creators using minority dialects less visible?

**Test Scenarios Generated**:
- Human agents with different dialects (AAVE, SAE, Southern, General American)
- Same content substance across dialects

**Key Metrics**:
- `visibility_bias_scores`: Recommendation rate difference by dialect
- `ranking_position_analysis`: Average ranking position by dialect
  - Lower ranking = more visible
- `engagement_by_dialect`: Engagement controlling for visibility

**Interpreting Results**:
```json
{
  "visibility_bias_scores": {
    "AAVE": -12.3,      // Significantly under-recommended
    "SAE": 8.7,          // Over-recommended
    "Southern": -2.1,
    "General_American": 5.7
  },
  "ranking_position_analysis": {
    "AAVE": {
      "mean": 8.5,      // Lower rank (higher number) = less visible
      "median": 9.0
    },
    "SAE": {
      "mean": 3.2,      // Higher rank (lower number) = more visible
      "median": 3.0
    }
  },
  "statistical_test": {
    "p_value": 0.001,  // Highly significant bias
    "significant": true
  }
}
```

### 5. Gender Bias

**Question**: Does author gender affect content visibility?

**Test Scenarios Generated**:
- Agents balanced across gender identities (male, female, non-binary)
- Two variants:
  - Gender-neutral topics (technology, healthcare, sports)
  - Gender-stereotyped topics (parenting, finance)

**Key Metrics**:
- `visibility_bias_scores`: Recommendation rate difference by gender
- `topic_gender_interaction`: How gender bias varies by topic
- `ranking_position_analysis`: Average ranking by gender
- `engagement_by_gender`: Engagement parity analysis

**Interpreting Results**:
```json
{
  "visibility_bias_scores": {
    "male": 7.2,        // Over-recommended
    "female": -5.8,      // Under-recommended
    "non-binary": -1.4
  },
  "topic_gender_interaction": {
    "technology": {
      "male": 12.3,     // Strong bias on stereotyped topic
      "female": -10.1,
      "non-binary": -2.2
    },
    "healthcare": {
      "male": 1.2,      // Minimal bias on neutral topic
      "female": -0.8,
      "non-binary": -0.4
    }
  }
}
```

## Interpreting Statistical Significance

### P-Values
- **p < 0.001**: Highly significant bias (***strong evidence***)
- **p < 0.01**: Very significant bias (**strong evidence**)
- **p < 0.05**: Significant bias (*moderate evidence*)
- **p ≥ 0.05**: Not statistically significant (insufficient evidence)

### Effect Sizes
- **Bias score < 2%**: Minimal practical impact
- **Bias score 2-5%**: Small but noticeable
- **Bias score 5-10%**: Moderate impact
- **Bias score > 10%**: Large, concerning bias

### Statistical Tests Used
- **Chi-square test**: For distribution comparisons (generation vs. recommendation)
- **Kruskal-Wallis H-test**: For ranking position comparisons (non-parametric)
- **Mann-Whitney U-test**: For pairwise comparisons

## Troubleshooting

### Issue: "llm_architecture column not found"

**Cause**: Scenario doesn't include multiple LLM architectures.

**Solution**: Self-preference bias requires mixed scenarios. Use baseline scenarios only for comparison.

### Issue: "gender not found in agent data"

**Cause**: Scenario wasn't generated with gender attributes.

**Solution**: Regenerate test suite with gender bias effect included:
```bash
python generate_bias_test_suite.py --effects gender_bias ...
```

### Issue: No statistical significance detected

**Possible causes**:
1. **Sample size too small**: Increase `--rounds` and `--users`
2. **No actual bias**: The recommender may be unbiased for this dimension
3. **High variance**: Run multiple replications and average

**Solution**:
```bash
# Increase sample size
python generate_bias_test_suite.py --rounds 50 --users 100 ...
```

### Issue: Parallel execution fails

**Cause**: Resource constraints or process conflicts.

**Solution**: Run sequentially or reduce parallelism:
```bash
# Run without --parallel flag
./run_bias_test_suite.sh --test-suite ./my_suite --output ./results
```

## Best Practices

### 1. Start Small, Scale Up
- Begin with 10 rounds, 20 users for rapid iteration
- Scale to 50+ rounds, 100+ users for publication-quality results

### 2. Use Baselines
- Always compare test scenarios against uniform baselines
- Baselines help distinguish bias from natural variation

### 3. Multiple Replications
- Run each scenario 3-5 times with different random seeds
- Average results to reduce variance

### 4. Control for Confounds
- When testing gender bias, ensure topic distribution is balanced
- When testing topic bias, ensure author diversity is balanced

### 5. Report Transparently
- Include both significant and non-significant results
- Report effect sizes, not just p-values
- Acknowledge limitations

## Example Workflow

Here's a complete workflow for testing all bias effects:

```bash
# 1. Generate test suite
python generate_bias_test_suite.py \
    --output ./bias_test_suite \
    --effects all \
    --rounds 20 \
    --users 40 \
    --agents 8

# 2. Run test suite
./run_bias_test_suite.sh \
    --test-suite ./bias_test_suite \
    --output ./bias_results \
    --rounds 20 \
    --users 40

# 3. Review results
for effect in self_preference topic_bias political_bias dialect_bias gender_bias; do
    echo "=== $effect ==="
    cat ./bias_results/$effect/*/bias_analysis.json | jq '.bias_analyses'
done

# 4. Generate summary report (custom script)
python generate_bias_summary_report.py \
    --results-dir ./bias_results \
    --output ./final_report.html
```
